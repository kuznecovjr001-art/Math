# Аудит движения и звука «Считалочки» (этап 1)

Срез: ветка `feature/living-motion-human-voice`, коммит `42e228e` + рабочее дерево на 2026-10-26. Только чтение кода;
приложение не запускалось, тесты не гонялись. `MissionPlayer.tsx` и `voice.ts` в момент аудита правились параллельно,
номера строк в них могут сместиться на 1–5.

Условные обозначения (колонка «События» и «Тест»):

- **Ввод.** Во всех 41 играх только тап/клик. `onPointer*`, `onDrag*`, `setPointerCapture` в играх нет (grep по `src/`: 0).
  Единственное касание pointer-событий — `MissionPlayer.tsx:239` (см. F3). `touch-action: manipulation` — `styles.css:35`.
- **Hover.** Единственный hover-зависимый стиль — `.zone:hover` (`styles.css:542`), игра `position`. Остальной интерфейс
  работает без hover.
- **P** = `OBJECT_PICKED`: уже шлёт плеер на любой `pointerdown` внутри `.game` (кнопки, `.tap`) — игре его слать не нужно.
  **D+/D−** = `OBJECT_DROPPED{hit:true/false}`: игра шлёт сама, когда предмет положен «в цель / не в цель».
  `ANSWER_*`, `HELP_REQUESTED`, `MISSION_COMPLETED` шлёт плеер (`MissionPlayer.tsx:106-192`).
- **Тест.** T1 = `renderToStaticMarkup` игры в режиме probe: в разметке нет маркеров ответа (`react-dom/server` уже в
  зависимостях React, jsdom не нужен). T2 = чистая функция/расчёт (вынести из компонента). T3 = последовательность
  событий: подменить `emit`, прокликать обработчики, сравнить список. T4 = Playwright (в плане по CLAUDE.md, не установлен).
- **B-safe.** Вариант B (`probe`, «Сам», `MODE_OF.B='probe'`, `MissionPlayer.tsx:61`) — самостоятельная проба. До ответа ребёнка
  нельзя показывать ни ответ, ни его проверку: бегущий итог, подсветку правильных пар/групп, `hit:false`, наклон весов.
  Движение, объясняющее решение, разрешено: в A сразу; в B и C — после ответа (как закрепление) или по ступеням помощи ≥2
  (существующая лестница `help`).

## 1. Сквозные находки

- **F1. Нет drag.** Все «перетаскивания» — тап «взять» и тап «положить» (Sort, Order, Boxes, Cups, Basket). Это хорошо
  для 4 лет и для доступности; настоящий drag — только как opt-in поверх тапа (P2.4). `OBJECT_DROPPED` пока означает
  «положили тапом в контейнер».
- **F2. Игра не знает, что за карточка.** `GameProps` = `{params, help, locked, onSubmit}` (`games/types.ts:12-18`,
  `MissionPlayer.tsx:231`). Варианта A/B/C и факта «ответил» в игре нет, поэтому B-safe анимации без нового пропа
  невозможны. Нужны `phase: 'learn'|'probe'|'review'` и `answered: boolean` (P0.1). Исключение — `facts`: `model:false`
  в B/C (`missions.ts:56`, `FactsGame.tsx:26`).
- **F3. События из игр не идут вовсе.** Игры не вызывают `emit`; `OBJECT_PICKED` приходит только из общего
  `onPointerDown` плеера (`MissionPlayer.tsx:239-241`; клавиатурное Enter/Space его не даёт). Следствие: `OBJECT_DROPPED`
  и реакция Счётика «показывает мимо цели» (`character.ts:62`, pointing) не используются; `STICKER_AWARDED` не шлёт
  никто (`App.tsx:120` `giveSticker`).
- **F4. Опасность hit:false в B.** `D−` включает pointing (`character.ts:62`) — это подсказка «не сюда». В B игры
  обязаны слать `D+` для любого допустимого действия (в корзину, на тарелку) и сообщать о правильности только через
  `ANSWER_*` после «Готово».
- **F5. Нажатие ответа молчит и не выделяется.** 31 игра отвечает через `Choices`/`NumberChoices`
  (`Choices.tsx:19`, кнопка `.btn.choice`). После тапа `locked` гасит ВСЕ кнопки до 0.45 (`styles.css:87`) на 0.6–2.5 с
  (`MissionPlayer.tsx:152`): выбранная кнопка не отличается от остальных, звука нажатия нет, у ребёнка ощущение
  «всё сломалось». Нужны состояния picked / right / wrong на самой кнопке (P0.3).
- **F6. Звук.** `sfx.*` зовут 8 игр и плеер (раздел 4). 33 игры беззвучны до результата; `good` одинаков для шага
  `final:false` и для итога (`MissionPlayer.tsx:162,172`); на финале и при выдаче наклейки отдельного звука нет.
- **F7. Уровни движения.** `prefers-reduced-motion` гасит всё (`styles.css:38-40`, дубль `:598-600`) — правильно и главнее.
  `data-motion=moderate|minimal` читает только `motion.css` и только для Счётика и облаков; существующие keyframes
  `styles.css` (`pulse :97`, `pop :357`, `arrive :397`, `turn :523`, `fall :575`) от `moderate|minimal` не зависят.
  `data-celebrations` выставляется (`App.tsx` effect по `settings`), CSS его не читает. Токены `--dur-*` в `styles.css`
  не используются: длительности 0.08–0.7 с прописаны числами.
- **F8. Не-композитные свойства в анимации.** `margin-left` в `.ribbon` (`styles.css:582`), `box-shadow` в `.btn` (`:84`)
  и в `pulse` (`:97-100`). Заменить на `transform` (ленты) — цель «только transform/opacity» (`MOTION_SYSTEM.md`).
- **F9. Утечка ответа в B уже есть.** `MeasureGame.tsx:39-49`: наклон `.beam` (`rotate(±12deg)`, transition 0.6 с) виден
  до ответа и сам показывает, какая чаша тяжелее. Кроме `measure` явных утечек не найдено: `hidden` не кладёт спрятанные
  предметы в DOM до ответа (`HiddenGame.tsx:23`), `facts` скрывает модель в B/C.
- **F10. Автосцена без ожидания.** `parcels` блокирует ответы 3.4 с таймерами (`ParcelsGame.tsx:22-23`) без индикации и
  без повтора по тапу; `flash` закрывает карточку через 1.5 с (`FlashGame.tsx:15,23`). При `reduced-motion` таймеры те же.
- **F11. Фокус.** Игра пересоздаётся по `key` (`MissionPlayer.tsx:232`): фокус уходит на `body` после каждой карточки.
  `.attention` — статичная пунктирная рамка (`styles.css:138`), движения нет. Видимый фокус есть (`:95`, 4 px).
- **F12. Конкурирующие «притягиватели внимания».** На экране задания: `pulse` кнопки помощи после ошибки
  (`styles.css:94`, `MissionPlayer.tsx:253`) + Счётик. Любая новая игровая анимация запускается событием, не циклом.
- **F13. Скрытая вкладка.** Счётик останавливает `TICK` при `document.hidden` (`Schetik.tsx:13`), но CSS-циклы
  (`sch-breathe`, `cloud 80s`) на `visibilitychange` не ставятся на паузу явно (браузер сам, WebView не гарантирует).

## 5. Бюджет и правила движения

- Двигать только `transform`/`opacity`; токены `--dur-press 110`, `--dur-appear 240`, `--dur-step 350`, `--dur-joy 700`
  (`motion.css`), для WAAPI — `tokens.ts` (`DUR`, `EASE`).
- Игровые анимации — по событию и однократные; бесконечные циклы только у Счётика и облаков карты.
- Одновременно анимируется не больше ~20 элементов; сетки по 100 (`beads100`, `chart100`, `complete100`) анимировать
  рядами (10 групп), не по клеткам; `will-change` не ставить заранее.
- Каждая анимация игры уважает три уровня: `prefers-reduced-motion` (всё выкл.), `data-motion=minimal` (только смена
  состояний без движения), `moderate` (без циклов). Сейчас это выполнено только для Счётика и облаков (F7).
- Любое «объясняющее» движение — отдельный флаг `explain` в игре: `phase==='learn' || help>=2 || answered`.
- Тяжёлых библиотек (Motion/Framer, 3D) не подключать до замера; хватает CSS и WAAPI (`element.animate`).
- Наклон устройства — не использовать; камера не нужна.
