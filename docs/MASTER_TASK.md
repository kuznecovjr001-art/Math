# ГЕНЕРАЛЬНОЕ ЗАДАНИЕ CLAUDE CODE — Math / «Считалочка»

Репозиторий: https://github.com/kuznecovjr001-art/Math
Цель: довести существующую русскоязычную «Считалочку» для детей 4–9 лет до аккуратного, безопасного Android-приложения, готового к самостоятельной публикации владельцем в RuStore. Сохранить работающий веб/PWA продукт.

Ты — единственный главный координатор. Используй 10 проектных субагентов из `.claude/agents/`; не запускай их всех сразу. Для специализированных проверок выбирай соответствующий `.claude/skills/<name>/SKILL.md` и существующие плагины из `.claude/settings.json` после проверки `/doctor`, `/plugin`, `/mcp`.

## Исходное состояние, которое надо подтвердить кодом
React 19, TS, Vite, PWA, 6 островов, 49 миссий, карта M01–M23, озвучка, собственная графика, профили, родительский раздел, `localStorage:mathkids:v1`. Актуализируй старый `CLAUDE.md` после сверки с README.

## Приоритеты
P0: корректность обучения, сохранение профилей и прогресса, Android, адаптивность, родительская панель и назначения, офлайн, приватность, QA и релиз.
P1: выразительные motion-эффекты, ненавязчивые окружающие анимации, optional device tilt.
P2: синхронизация между устройствами, облачная аналитика, покупки, реклама и другие расширения — не реализовывать до отдельного решения владельца.

## Выполнение
1. Изучи `docs/MATH_IMPLEMENTATION_ROADMAP.md`. Создай/проверь отдельную рабочую ветку; не переписывай `main`.
2. Этап 00: прогони тесты, составь инвентаризацию кода, зафиксируй SHA, список блокеров, набор целевых Android-устройств и экранов. Не сообщай о тестах, которых не запускал.
3. Работай последовательно по этапам 01–11 из roadmap; можно параллельно выполнить независимые исследовательские проверки, но не допускать одновременного редактирования файлов разными агентами.
4. На каждом этапе дай конкретные задания нужным 1–2 агентам. Пусть они описывают ограничения и возвращают компактный результат, а не вставляют все исходники в контекст. Разработка — небольшими PR с TDD и code review.
5. Метрики родителя: НЕ считать `missionCompleted` подтверждением освоения. Развести показ карточки, первую попытку, правильное решение без помощи, завершение миссии, освоение навыка, подтверждённый повтор. Особо проверить `correct && final === false`.
6. UX: одно главное действие на экране, ребёнок может действовать без чтения, крупные цели касания, картинки занимают подходящую часть экрана, нет избыточных декораций. Нужны phone/tablet portrait и landscape. Анимации реагируют на нажатие, drag/drop и состояние ребёнка; уважать reduced motion.
7. Parent: отдельно protected взрослый режим (имеющийся математический барьер — лишь от случайного входа), назначение конкретных миссий и планов, выбор стартового острова, просмотр прогресса, истории и причин рекомендации повторов.
8. Storage: бесшовная миграция `mathkids:v1`, резервная копия локально, экспорт/импорт, детские профили без регистрации; исключить сторонние трекеры и обязательную сеть.
9. Android: выбрать поддерживаемую и актуальную Capacitor версию по Context7/официальным docs, настроить Gradle CI, native Back, safe areas, offline embedded assets, proper lifecycle. Не считать Chromium screenshot доказательством работы на Android; проверить через emulator/device.
10. QA: smoke каждой из 49 миссий, автоматизация ключевых маршрутов Vitest/Playwright/Maestro, accessibility/permissions/voice, отсечение критических багов; сравнивать фактические скриншоты на телефоне и планшете.
11. RuStore: проверить требования на дату публикации, подготовить релизную сборку, метаданные, лицензии, политику приватности, скриншоты, инструкции для ручной подписи. Никогда не помещать keystore/секреты в Git или логи; не публиковать без владельца.

## Управление процессом
- Если пользовательские решения не требуются, не задавай повторяющихся уточнений и не прекращай работу между техническими этапами.
- Если нужна подпись, доступ к аккаунту, реальное устройство, ручная педагогическая апробация или правовые подтверждения, честно поставь `BLOCKED_MANUAL`, доведи остальные независимые задачи, не имитируй успех.
- Каждый этап фиксируй в `docs/implementation-progress.md`: статус, SHA/PR, выполнено, выполненные тесты, причины отказа, следующая задача.
- Используй команды сборки и тестирования из package.json, запрашивая обновление только при необходимости.
- Следи за токенами: исследование локально и точечно, краткие результаты субагентов, без повторного чтения большого набора картинок и аудиофайлов.
- Не скрывать регрессии и не «исправлять» их выключением тестов.

## Критерии завершения
* Android Debug APK реально собран и запущен; релизная сборка подготовлена и подписана только безопасным способом.
* Все 49 миссий доступны в нужном порядке и проходимы, учебные данные валидны.
* На Android-телефоне/планшете не режутся картинки, текст и кнопки; обратная связь на касания комфортная.
* Родитель видит достоверный прогресс и способен назначить миссии без порчи учебного пути.
* Офлайн с первого запуска, корректное восстановление после закрытия, миграция данных и экспорт/импорт.
* CI зелёный, документация обновлена; для каждого незавершённого проверки нет ложной пометки PASS.
* Имеется финальный отчёт `GO / NO-GO` для загрузки в RuStore с отдельно перечисленными действиями владельца.
